# Manga Nihongo

**Stories that teach real Japanese.**

Manga Nihongo is a mobile-first PWA for English-speaking anime and manga fans (roughly N5–N4). You read a short manga episode, tap the phrases people actually say, and see how *anime Japanese* differs from *real Japanese*. Story first, vocabulary lists never.

This repository is the MVP: **Tokyo Days — Episode 1 "Hajimemashite" (はじめまして)**, playable from start to finish.

## MVP features

- **Home** — series card with Continue Reading, XP, streak, Today's Review, bottom navigation
- **Stories** — Tokyo Days episode list (Episodes 2–5 are "Coming Soon")
- **Manga Reader** — vertical scroll, 10 scenes, speech / thought / narration bubbles, first-run tap guide
- **Expressions** — 5 tappable phrases (って, じゃん, マジで？, いいよ, よろしく) with a compact bottom sheet and a full detail view: Anime vs Real scores, Work / Casual scores, Casual → Standard → Polite transformations, usage with friends / teacher / boss
- **Furigana** — Beginner / Standard / Immersion, saved per device
- **Story Choice** — "How would you respond naturally?" with different feedback for each answer
- **Episode Complete** and **Review** (3 questions)
- **XP** (no double counting), **streak**, and all progress in `localStorage`
- **PWA** — manifest, installable, standalone, basic service worker, safe-area aware, `prefers-reduced-motion` respected

XP rules: first time opening an expression +5, correct Story Choice +20, finishing the episode +100, each correct review answer +10. Every reward is granted once per key (see `xpAwarded` in the stored state).

## Tech stack

Next.js (App Router) · TypeScript · Tailwind CSS v4 · shadcn/ui-style components (Radix Dialog, class-variance-authority, lucide-react) · localStorage behind a storage adapter.

The artwork is original SVG (no existing anime or manga is used). It is drawn from data, so real images can replace it later without touching the UI.

## Getting started

```bash
npm install
npm run dev        # http://localhost:3000
npm run lint
npm run build && npm run start
```

Open it on an iPhone (or Chrome DevTools at 390px wide) and use *Share → Add to Home Screen* to try the standalone mode. The service worker only registers in production builds.

Placeholder app icons are generated by `python3 scripts/generate-icons.py` (Pillow + a CJK font). Replace the files in `public/` with final artwork at any time.

```

  components/             shared UI (ui/ = button, sheet), layout, logo, score stars
  features/
    home/ stories/ me/    tab screens
    manga/                reader, panels, bubbles, furigana text, SVG art
    expressions/          bottom sheet, detail view, meters
    challenges/           Story Choice
    episode/              Episode Complete
    review/               Review session
  content/                data only — no UI
    episodes/ expressions/ characters/ challenges/ review/ furigana.ts
  lib/                    pure helpers (dates, furigana, segments, xp, storage adapter)
  stores/                 progress store (useSyncExternalStore + pure transitions)
  types/                  content + progress types
public/                   icons, sw.js
scripts/                  icon generator
```

### How content is wired

- `content/episodes/tokyo-days-ep1.ts` holds the script. A dialogue links to expressions with `expressionIds`; the matching text becomes tappable automatically.
- `content/furigana.ts` is a fixed word → reading dictionary with a level. Beginner shows every reading, Standard only the harder ones, Immersion none.
- `Scene.image` is either a key for a built-in SVG background or an image path such as `/manga/ep1/s1.webp`. Swapping in final art only needs that one value.

### Persisted state

Stored under `manga-nihongo:progress:v1`: `currentEpisode`, `currentScene`, `episodeCompleted`, `openedExpressionIds`, `learnedExpressionIds`, `xp`, `streak`, `lastStudyDate`, `furiganaMode`, `reviewResults`, `storyChoiceResult` (plus `xpAwarded` and `hasSeenTapGuide`). Data is validated when loaded, so a corrupted value falls back to defaults.

All reads and writes go through `src/lib/storage.ts`. To move to Supabase, implement `StorageAdapter` and pass it to `configureStorage()`; the state transitions in `stores/progress-store.ts` are pure functions and can run on a server too.
